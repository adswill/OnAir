# Own mode-list entries for protocols inside a shared entry (3.9, worker w1c)

Rule: one mode-list entry per protocol. The first 20 rows of MODES-39-CANDIDATES.md with Status SPLIT, feasibility A or B and effort S were
checked against the code. Branch `feat39-w1c`.

## Added: six CubeSat framings, families 840 .. 855

The family numbers 840 .. 869 hold ten modes at the stride of three that a mode needs (family N, active standard N + 1, engine standard
N + 2), so ten is the most this block can take; six were separable.

| Row | Entry | Family | Active / engine std | Framing (`cubesat::Framing`) | Own id |
|---|---|---|---|---|---|
| 1 | AX100 Mode 5 | 840 | 841 / 842 | `Ax100Mode5` (ASM 0x930B51DE, Golay, RS) | `ax100m5` |
| 2 | AX100 Mode 6 | 843 | 844 / 845 | `Ax100Mode6` (RS inside HDLC, G3RUH) | `ax100m6` |
| 3 | USP | 846 | 847 / 848 | `Usp` | `usp` |
| 7 | NGHam | 849 | 850 / 851 | `Ngham` | `ngham` |
| 9 | U482C | 852 | 853 / 854 | `U482c` | `u482c` |
| 14 | BEESAT / Mobitex | 855 | 856 / 857 | `Mobitex` | `beesat` |

Where the protocol was found: `core/src/cubesat/cubesat_rx.cpp` (`Impl::onHdlc`, `onAsm`, `onMore` and `accept()`), the framings in
`cubesat_proto.h` / `cubesat_more.h`, the row "CubeSat telemetry" (family 61) in `app/ui/mode_table.cpp` and its line in MODES.md.

### How each entry works (no new DSP)

- Every entry is a view onto the one `CubesatReceiver` (`rxCube_`). `CubesatReceiver::setFramingMask(mask)` (default 0 = every framing, so
  family 61 is unchanged) makes `accept()` drop frames of other framings and makes `telemetry()` report only the frames and per-framing counts
  of the chosen ones. The demodulators and decoders run exactly as before; the engine sets the mask at start from the active standard
  (`engine_start.cpp`).
- Table: `cubesatViews()` in `cubesat_rx.h` / `.cpp` (family, id, name, framing); `cubesatViewTuning(i)` gives the CubeSat telemetry radio
  settings under the entry's own id, name and standard and is listed in `modes.cpp` `table()`.
- Engine dispatch: the sample feed's existing `a == 62` branch also takes the view standards (`cubesatViewForActive(a)`), so the final
  `else rx_.feed` is still the only `else`. Reset, configure, offset / dial and `pollStd` have one `case` per entry. The test signal
  (`modes.cpp`) is `makeCubesatSynth` with `modeOpt[0] = 1 + framing`, the single-framing signal that already existed.
- App: a mode-table row per entry (group Satellites, `N_()` sub line with a German translation in `app/i18n/de.txt`), the CubeSat panel
  (`kCubesatUi`) for each family; its `live()` accepts the view standards. The family 61 row now says the six also have entries of their own.
- Generated: MODES.md (`gen_modes_list.py`), the web schema (`gen_web_schema.py`), Android modes and results map (`android/tools/gen_modes.py`,
  `gen_results_map.py`); `server/web/web_policy.cpp` classifies the six ids as restricted like every other mode.
- Result files: the entries share the CubeSat results slot (`"cubesat"`, 62), as they share the receiver.

### Tests

`tests/cubesat/test_cubesat_views.cpp` (ctest `cubesat_views`): the tables (+1 / +2 numbers, unique ids and framings, the tuning table, the
shared entry untouched); one stream with every framing and seven receivers (six views, one unfiltered): each view reports its own framing
and none other, the unfiltered one still hears all ten; the engine started through `setStandard(family + 2)` with the entry's own test signal
decodes that framing and no other and reports standard family + 1. The existing `cubesat_engine`, `cubesat_rx`, `cubesat_more` and
`cubesat_proto` tests cover the shared entry. Generated signals only: no recording was used for these entries (the framings themselves were
checked against gr-satellites vectors when they were written, see CUBESAT-3.9.md).

## Skipped, with the reason

| Row | Protocol | Why |
|---|---|---|
| 4 | FUNcube / AO-73 | decoded by the Smart CubeSat chains (AO-40 FEC), not by the shared receiver; a view would need a different receiver and engine hook |
| 5 | Fox DUV | not decoded anywhere (only a satellite name in the table) |
| 6, 20 | FX.25, IL2P / packet | decoded in the packet receiver, whose FEC sink drops which code made a frame; a view needs a change in `packet_rx.cpp` shared with APRS and Packet |
| 8 | Linear transponder tracker | no such decoder or tracker in the code |
| 10 - 13, 15 - 18 | LilacSat-1, Light-1 / BlueWalker, TT-64, OpenLST, OPS-SAT, Delfi, S-NET, Hello World / Reaktor | only rows in the gr-satellites table with `GrFraming::Other`: OnAir has no decoder for them, so nothing to separate |
| 14 | BEESAT-1 / BEESAT-9 | done (one entry with Mobitex, which is the framing these satellites use) |
| 19 | AO-7 | beacon frequencies in the satellite detector only, no telemetry decoder |

Rows 1 .. 20 gave six entries; the rest of the 20 were skipped for the reasons above, so no more family numbers were used (858 .. 869 stay free).
