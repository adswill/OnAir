# Issue fixes from the 3.7 test replies (feat38-iss2)

Bugs reported in GitHub replies after 2026-11-09 16:00 UTC, fixed on branch feat38-iss2 (based on integ-38).

| Issue | What was wrong | Change | Checked |
|---|---|---|---|
| #440 | The Inmarsat panel never asked the codec loader for `aeroambe`, so `onair-codec-aeroambe` was never registered and the Voice tab always said no codec was installed. | `app/inmsat/inmsat_ui.cpp`: the panel tick registers the plug-in, and the Voice tab shows the standard codec line with the notice prompt. | Syntax check only. Not run with a real plug-in. |
| #472 | The Windows installer deleted every `*.dll` in the install folder on an update, including DLLs the user put there (faad2, fobos_sdr, the SDRplay API, libmbe, codec plug-ins, DRA). | `packaging/windows/onair.nsi`: those names, which the package never ships, are set aside before the delete and put back before the new files are copied. | Not compiled: the local makensis crashes even on the unchanged script. The release workflow builds it. |
| #471 | Transmit audio files were decoded into memory with a 10 minute cap, so a longer file restarted at 10 minutes. | `core/src/audio/audioin.cpp`: a file longer than 10 minutes stays open and is decoded while it plays, then loops at its real end. Shorter files work as before. | New test `audio_file_long`: a 30 s file and a 700 s file match sample for sample through the end and into the loop. The old code fails it (the length is reported as 600.06 s). |
| #335 | A packet whose second header is proprietary (SAP 9, MFID 16, Motorola compressed IP/UDP) restarted the assembly, so its blocks were dropped, and the LRRP parser only knew plain IPv4/UDP. | `core/src/dmr/dmr_link.cpp`: the proprietary header counts as a block and its octets are kept. `dmr_lrrp.cpp`: `parseDmrLrrpCompressed` reads the document from inside that header. It is accepted only when the document's length ends exactly at the end of the data and every token is known. Token 0x34 (time) is now skipped. | `test_dmr_lrrp` uses the reporter's octets and gets 45.32213, 8.88696. `test_dmr_lrrp_air` sends those octets through the receiver (simulated signal: clean, 400 Hz with 8 ppm, and 18 dB SNR): 31 of 31 reports decoded, 0 before the fix. The packet CRC in the reporter's log does not match any CRC-32 convention tried, so the check is the document length. |
| #468 | The codec helper compiled the wrapper without `MBE_STATIC`, so MinGW declared every `mbe_*` function dllimport and the link against the static library failed. | `tools/codec-builder/build-codecs.ps1` and `build-codecs.sh` pass `-DMBE_STATIC=1`. | The wrapper compiles for all five plug-ins against mbelib-neo 2.6.2 on macOS. Not run on Windows. |
| #169 | A Mini V1 worked with FTDI driver 1.3 and not with 1.4. | `core/src/source/usb_diag.cpp`: the Windows hint suggests the previous FTDI driver. | Syntax check. |

Not fixed here, waiting for the reporter: #139 (desktop top-bar buttons do nothing on a 640x480 Pi screen, not reproduced), #470 (Pi 5 renders with llvmpipe), #408 (TETRAPOL recording attached, not downloaded), #192 (HaLow IQ on Google Drive, not downloaded).
