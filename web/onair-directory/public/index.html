No receivers listed

Nobody is listed right now, or nothing matches your filters. A receiver appears here only when its owner turns the directory on in onair-server.

To list yours, add these to the server settings file, start onair-server --web, read the preview it prints, then add the confirmation code it gives:

web_directory=1
web_directory_url=https://web.on-air.dev
web_public_url=https://radio.example.org
web_directory_loc=54.69,25.28     # optional, or a locator such as KO24pq
web_directory_radio=HackRF Pro
web_directory_desc=Wideband receiver on the roof
web_directory_ack=<code from the preview>

The address must be HTTPS. Only name, address, rough location, coverage and listener counts are sent, every 5 minutes. Full steps: OnAir Web guide and directory notes.

Listen to a receiver

You need nothing but a browser. No account, no download.

  1. Open the Receivers tab. Each row is a radio somebody shares. The bar shows which frequencies it covers; Listeners shows how many people are on it out of how many it allows (for example 2/6).
  2. Pick one that covers what you want. Use the band buttons (FM, Air, HF ...) or the search box. Rows with no free slot (3/3) are full: try another or come back later.
  3. Click Listen. The receiver opens in a new tab. It is the owner's own page, not ours.
  4. Press the play or audio button there and choose a frequency. Your browser needs a click before it will play sound.
  5. If it asks for a password or invite, the owner keeps it private. Ask them; nothing here can give you one.

Something wrong with a receiver? Use Report next to it. Listings are written by their owners and nobody checks them first.

Full guide for listeners and owners: OnAir Web guide or the wiki page.

List your receiver here

Listing is optional and off by default. Nobody has to approve it; your server signs each message so nobody else can edit your entry.

Before you start: you need a running OnAir Web server that listeners can reach over HTTPS (see Run your own, step 6).

  1. Open the server settings file (on Linux ~/.config/onair/server.conf) and add: 
    web_directory=1
web_directory_url=https://web.on-air.dev
web_public_url=https://radio.example.org
web_directory_radio=HackRF Pro
web_directory_desc=Wideband receiver on the roof
web_directory_loc=54.69,25.28
    Replace web_public_url with the HTTPS address listeners open. The location is optional (leave the line out for none); a Maidenhead locator such as KO24pq works too. Set web_directory_loc_decimals=2 to keep it to about 1 km.
  2. Start the server: onair-server --web. Nothing is sent yet.
  3. Read the preview it prints. It shows the exact data that would be sent, where it goes, and a confirmation code.
  4. Add the code to the settings file as web_directory_ack=<code> and restart. If you later change the name, address, location or description, you get a new code and must look again.
  5. Wait about a minute. Your receiver appears on the Receivers tab and is refreshed every 5 minutes. If the server stops, the entry disappears after about 15 minutes.
  6. To remove yourself: run onair-server --directory-remove, or set web_directory=0.

What is sent: name, description, address, rough location, radio name, frequency coverage, listener limit and the current number of listeners. Never sent: who listens, what they listen to, or your own IP address. Details: directory notes.

Run your own receiver

One radio, many listeners: each listener gets their own virtual receiver inside what your radio captures. Receive only.

The 3.0.0 downloads contain the desktop app but not the onair-server program yet, so for now you build it from source (steps 1 and 2). It is one command per step. If you only want to try OnAir itself, the app is on the 3.0.0 release page.
  1. Get the source (needs git, CMake, a C++ compiler and Rust; the build notes list the packages per system): 
    git clone --branch v3.0.0 https://github.com/adswill/OnAir.git
cd OnAir
  2. Build the server. 
    # Linux and macOS
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --target onair-server -j4

# Windows (Developer PowerShell)
cmake -S . -B build
cmake --build build --config Release --target onair-server
  3. Start it. Plug in your radio, then: 
    # Linux and macOS
./build/onair-server --web --web-lan

# Windows
build\Release\onair-server.exe --web --web-lan
    No radio yet? Add --device test for the built-in test signal.
  4. Open it. On any computer or phone on your network go to http://<address of the server>:8073. On the server itself use http://127.0.0.1:8073. On plain HTTP only private network addresses are let in.
  5. Choose who may listen. Add to the settings file, then restart: 
    web_auth=password          # open, password or invite
web_password=choose-eight-or-more
web_max_users=6
    Invite links look like http://host:8073/#invite=TOKEN. Start with a password or invites: open access means anyone, and they share your upload bandwidth.
  6. Put it on the internet without opening your router. Install cloudflared and run: 
    cloudflared tunnel --url http://127.0.0.1:8073
    It prints an https://....trycloudflare.com address. That is your public HTTPS address; it changes each time you start it. For a fixed name use a named tunnel or a reverse proxy: see the guide.
  7. List it here (optional): follow List your receiver, using the address from step 6 as web_public_url.

All settings, limits, frequency restrictions and the admin API: OnAir Web guide, wiki, website copy.

FAQ

Can listeners transmit or control my radio?
No. OnAir Web is receive only. Listeners tune their own virtual receiver; they cannot change your radio's frequency, gain or mode, and the protocol refuses transmit requests.
What does this directory store about listeners?
Nothing. It never sees who listens: servers send only a count. This page uses no cookies and no analytics. If you share your location for distances, it stays in your browser.
What does it store about receivers?
What the owner chose to send (see List your receiver). The server's IP address is not stored.
Are the listed receivers checked?
No. Entries are self-registered. A green dot means the directory asked the address and an OnAir server answered; grey means not checked. Use Report if something is wrong.
Is it legal to share my receiver?
Rules differ by country. Receiving some services (for example private or encrypted traffic) can be restricted, and you are responsible for what your receiver offers. OnAir keeps voice and pager decoders off until the host accepts a legal notice, and you can limit frequencies. This is not legal advice.
Why is my receiver not showing?
Check that you added the confirmation code, that the public address starts with https:// and opens from outside your network, and that the server's clock is right (within 5 minutes). Give it a few minutes.
Where do I ask for help?
OnAir Discord or GitHub issues.
